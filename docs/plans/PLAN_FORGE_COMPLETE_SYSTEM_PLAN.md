# Plan-Forge: complete system implementation plan

## Context
Implement the supplied Plan-Forge specification in `github.com/danielckv/agentic-plan-forge`: a Go client (`plan-forge`) with an embedded three-page React UI, a same-repo Go relay (`plan-forge-relay`), `.docx`/`.pdf`/`.md` ingestion, Tree-sitter repository grounding with documentation drift, staged tool-free multi-avatar deliberation, a Confluence-grade spec + manifest compiler with dual 9-hour-day/agent schedules, Solo and Remote collaboration, and host integrations for Claude Code, OMP and AGY. Installation MUST be one command that installs the binary and registers `/plan-forge` and `/plan-config` skills in every detected local agent, with the binary install documented in the README. Also exclude `.agents/` and other machine-local agent state from version control. The repository today contains only OSS scaffolding (HEAD `8484cac` on `main`, no remote); every application path below is NEW.

Supplied-spec corrections applied (each verified this session): module path uses the real repo identity, not `github.com/org/plan-forge`; `//go:embed` cannot reach outside its package (https://go.dev/pkg/embed/) so the embed lives in `web/embed.go`; `[]byte` JSON payloads base64-encode, so payloads are `json.RawMessage`; concurrent text edits use central OT; "zero lag" becomes a measurable loopback test; "thinking streams" become public progress/rationale summaries; AST presence alone never proves COMPLETED; host plan-mode entry is instructed by the skill, not forced by exit code.

## Execution lanes and ordering
Every step leaves the tree building with existing checks green. Serialize only on produced contracts:
1. Step 0 (repository hygiene) — first, alone.
2. Step 1 (module, contracts, protocol, config, CLI skeleton) — serial; every later lane consumes its types.
3. After Step 1, parallel lanes with disjoint directories: Step 2 (`internal/ingestion`, `internal/ast`), Step 3a host adapters (`internal/host` minus installer), Step 4 authority/relay/window (`internal/collab`, `internal/session`, `internal/relay`, `internal/window`, `cmd/relay`), Step 5a frontend toolchain + Page shells (`web/` except `web/embed.go`).
4. Step 3b avatars + synthesizer (`internal/avatars`, `internal/synthesizer`, `internal/storage`) after Steps 2 and 3a contracts are merged.
5. Step 5b Pages 1–3 wiring after Steps 3b and 4; this lane creates `web/embed.go` and `internal/app` (composition) last.
6. Step 6 install/skills/hooks/release after Steps 3a and 5b; README `## Install` and `## Build from source` sections land with it.
Mutating parallel workers MUST run in isolated worktrees (one per lane) and be merged by one integration owner; no lane edits another lane's directories. `go.mod`/`go.sum` and `web/package-lock.json` changes are owned by the integration owner and merged serially.
`cmd/client` uses a command registry: Step 1 creates `cmd/client/main.go` with `register(name string, run func(ctx context.Context, args []string) int)`; each lane adds only its own `cmd/client/cmd_<name>.go`. A checkpoint runs once its lane and every lane it references are merged (Checkpoint 3's Mermaid assertion runs after the Step 5a merge).

#### Wire and schema contract

NEW `internal/relay/protocol.go` defines:

```go
type SessionMode string // SOLO, REMOTE
type WSEventType string
type WSEnvelope struct {
    Version uint16 `json:"version"`
    SessionID string `json:"session_id"`
    SenderID string `json:"sender_id"`
    EventID string `json:"event_id"`
    EventType WSEventType `json:"event_type"`
    Seq uint64 `json:"seq,string"`
    Revision uint64 `json:"revision,string"`
    Epoch uint64 `json:"epoch,string"`
    Timestamp time.Time `json:"timestamp"`
    Payload json.RawMessage `json:"payload"`
}
```

`version` is 1. Authority supplies sender identity, sequence and timestamp; peer-submitted values cannot impersonate a member. Client commands use seq `"0"`. Decimal-string counters avoid JavaScript integer precision loss. `event_id` is UUID, unique per command; retrying the same ID with identical content returns prior acknowledgement, changed content yields `EVENT_ID_CONFLICT`. Decode max 4 MiB per frame, reject unknown event types/schema versions, duplicate JSON keys, trailing JSON, invalid UTF-8, and oversized nested payloads. Each strict schema has `additionalProperties:false`; enum unknowns are errors rather than ignored fields.
- `STATE_SNAPSHOT` never embeds document text or draft bodies: it carries `content_hash` values and clients fetch `TEXT_SNAPSHOT` and draft bodies separately. A compiled spec plus manifest over 1 MiB combined fails the synthesizer stage with `ErrBound` (keeping one `AVATAR_DRAFT` frame inside the 4 MiB cap after JSON escaping). Document text over 512 KiB is rejected by the OT authority (`TEXT_REJECT{reason:"too_large"}`).

Preserve all nine business event names. Required payload fields:
- `TEXT_DELTA`: `document_id` (v1 has exactly one editable document; constant `prd`, unknown IDs rejected), `base_version` (decimal string), `updates` (array of `{client_id, changes}`; `client_id` = `<member_id>:<instance>`, authority-validated; `changes` = CodeMirror `ChangeSet.toJSON()`). Clients send `sendableUpdates(state)` uncomposed, one entry per local update, because `receiveUpdates` confirms own updates one-to-one by client ID. Central OT, not Yjs and not raw text offsets.
- `PAGE_TRANSITION`: `from`, `to`, `expected_revision`, `baseline_hash`; authority validates legal transition and freeze barrier.
- `CYCLE_START`: `run_id`, `baseline_hash`, `graph_hash`, `cycle`, `executor_id`, `lease_epoch`.
- `AVATAR_THOUGHT`: `run_id`, `avatar_id`, `cycle`, `status`, `public_summary`; never relay provider private thinking blocks.
- `AVATAR_DRAFT`: `run_id`, `avatar_id`, `cycle`, `draft_id`, `draft_revision`, `schema_id`, `content`, `content_hash`, `complete`.
- `AVATAR_CRITIQUE`: `run_id`, `cycle`, `issues` (typed Critique array).
- `DECISION_PROMPT`: `decision_id`, `run_id`, `input_revision`, `question`, `options` (2–4 ID/label/tradeoff objects), `recommended_option_id`.
- `DECISION_RESOLVE`: `decision_id`, `input_revision`, `option_id`, `actor_id` (authority-supplied).
- `PLAN_APPROVED`: `approval_id`, `approved_revision`, `spec_sha256`, `manifest_sha256`, `bundle_id` (= hex SHA-256 over the 64 raw bytes: the 32-byte spec digest followed by the 32-byte manifest digest), `persisted_by` — hashes copied from the executor's `ARTIFACT_SAVED`.

Additional control events are explicitly separate from those nine: `HELLO`, `STATE_SNAPSHOT`, `REPLAY_REQUEST`, `PRESENCE`, `FREEZE_REQUEST`, `LEASE_CLAIM`, `LEASE_GRANTED`, `LEASE_RENEW`, `LEASE_RELEASE`, `LEASE_LOST`, `FENCED`, `CANCEL`, `ERROR`, `APPROVE`, `APPROVAL_PREPARED`, `ARTIFACT_SAVED`, `ARTIFACT_SYNCED`, `SYNTHESIZE_REQUEST`, `RETRY_STAGE`, `EDIT_BASELINE`, `INGEST_APPEND`, `RUN_ASSIGNED`, `AMBIGUITY_RESOLVE`, `INVITE_REVOKE`, `MEMBER_REMOVE`, `EXECUTOR_LEFT`, `EXECUTOR_LOST`, `RUN_SUPERSEDED`, `ALREADY_RESOLVED`; doc-channel replies `TEXT_ACK`, `TEXT_REJECT`, `TEXT_UPDATES`, `TEXT_SNAPSHOT`, `TEXT_CHECK`. Version them in the same protocol. Every control payload uses the common session/revision metadata plus fields defined in the collaboration step.

Canonical JSON Schemas live in NEW `internal/contracts/schema/` and are embedded into Go. Use `github.com/santhosh-tekuri/jsonschema/v6` for Go schema validation and Ajv 2020 in the frontend. Typed Go structs and TS interfaces MUST pass the same positive/negative JSON fixture corpus. Disable network `$ref` loading; schemas are local embedded resources only. Schema tests explicitly cover unknown keys and unsupported versions. No model output becomes trusted merely because JSON parses.

No absolute machine paths, credentials, raw model transcripts or original uploaded documents.

On first write, `StateStore`/`ArtifactStore` create `.plan/.gitignore` containing exactly four lines `*`, `!.gitignore`, `!synthesized_spec.md`, `!plan_manifest.json` (default-deny inside users' repositories; the two artifacts stay trackable, so `git check-ignore .plan/synthesized_spec.md` exits 1). Local mutable state: `.plan/state.json` (0600; run log, revisions, receipts — never relay/room/member/invite secrets, invite URLs, absolute paths or prompt text; a schema test enforces this), `.plan/cache/`, `.plan/transactions/` (journal), `.plan/history/<ts>/` (prior approved pairs, keep 5), `.plan/verification/`, `.plan/lock`. `ArtifactStore.Commit` uses same-directory staging, a journal, backup of prior generation, fsync, spec replacement, then manifest replacement as commit marker. Readers expose only hash-matching pairs. On restart, if both new hashes match, finish the journal; otherwise restore the prior pair. Use OS-specific atomic replacement on Windows and directory fsync where supported. Test injected crash/failure after every write/rename. Neither disk-full nor partial remote delivery returns success. Keep the committed pair when post-commit peer delivery fails; show pending peers, never claim distributed atomicity.

### Step 2 — ingestion, Tree-sitter grounding and documentation drift (Tasks 2.1–2.3)

Depends on shared contracts. Client-only packages (`//go:build client && !server` on files that import CGO or `os/exec`); the relay never links them.

#### Document parsers (NEW `internal/ingestion/`)

- Files: `ingest.go` (router), `docx.go`, `pdf.go`, `ocr.go`, `bounds.go`, `normalizer.go`, fixtures in `internal/ingestion/testdata/`.
- Router `Ingest(ctx context.Context, name string, r io.ReaderAt, size int64) ([]contracts.DocumentBlock, IngestReport, error)`: routes by extension AND magic bytes (`PK\x03\x04` for `.docx`, `%PDF-` for `.pdf`); `.md`/`.txt` are UTF-8 text (BOM stripped, invalid UTF-8 rejected). Unknown/mismatched types return `ErrUnsupportedFormat`; never a silent plain-text fallback.
- Bounds (typed `ErrBound{Name, Limit, Observed}`): file ≤25 MiB (UI) and ≤50 MiB (CLI); PDF ≤500 pages; DOCX ZIP ≤10,000 entries, ≤256 MiB total uncompressed, per-entry compression ratio ≤100:1 (zip-bomb guard); entries escaping the package root rejected; XML token count and nesting depth capped (1,000,000 tokens, depth 256). Go `encoding/xml` does not resolve external entities.
- DOCX (stdlib `archive/zip` + `encoding/xml` token stream; no third-party dependency): `word/document.xml` paragraphs `w:p` → text from `w:r/w:t`, honoring `w:tab` and `w:br`; heading level from `w:pStyle` resolved through `word/styles.xml` (`w:outlineLvl` or built-in `Heading N` names); lists via `w:numPr` (`numId`+`ilvl`) resolved through `word/numbering.xml` (`w:num`→`w:abstractNum`→`w:lvl`, emitting marker kind bullet/decimal and depth); tables `w:tbl/w:tr/w:tc` → table block rows. Numbering restarts/`w:lvlOverride` beyond start values are reported as `IngestReport.Warnings` ("list numbering approximated"), not guessed. Password-protected/encrypted DOCX (OLE compound file signature `D0 CF 11 E0`) → `ErrEncrypted`.
- PDF born-digital: `github.com/ledongthuc/pdf` `v0.0.0-20260907135840-6c8c28e0e8a0` (BSD-3-Clause; API `Open`, `NumPage`, `Page(n).GetTextByRow()`, `GetStyledTexts()` verified from its README). Group rows into lines by Y position, infer headings from font size ≥1.2× median body size, record page per block. Encrypted PDFs → `ErrEncrypted`. Multi-column layouts are reading-order approximations; emit a warning when two or more distinct X clusters exist on a page.
- Scanned PDF: a page with <10 extracted glyphs is "unparsed scanned". If `exec.LookPath("pdftoppm")` and `exec.LookPath("tesseract")` both succeed: `pdftoppm -r 200 -png -f N -l N <pdf> <tmpdir>/p` then `tesseract <png> stdout tsv -l <ocr_language>`; parse TSV words/confidence; record `{tool versions, dpi:200, mean confidence}` provenance. #### Plan-status hook evidence

`CheckState(ctx, repo) (PlanStatus,error)` compares manifest base/hash and target signatures against a fresh bounded AST snapshot. All symbols present without receipts remains IN_PROGRESS with 'structure matched; behavior unverified'. Docs-only and UX tasks require explicit checks; never invent AST evidence for them.

#### OT document authority (NEW `internal/collab/authority.go`, untagged)

- Library choice: browser uses `@codemirror/collab` 6.1.1 + `@codemirror/state` ^6.7.6 + `@codemirror/lang-markdown` ^6.5.2. Go is the central authority (CodeMirror collab model, https://codemirror.net/examples/collab/). No equivalent Go code exists; port only `ChangeSet` JSON validation + apply, never rebase/compose.
- Authority state per document: `text []uint16` (UTF-16, matches CodeMirror offsets), `version uint64`, bounded update log (keep all while <10k entries and <8 MiB; compact below the minimum acked version of connected members).
- `Push(memberID string, baseVersion uint64, updates []Update) (newVersion uint64, err error)` where `Update{ClientID string; Changes json.RawMessage}`: accept only when `baseVersion == version`; otherwise reply `TEXT_REJECT{document_id, head_version, updates | resync:true}` and the client rebases via `receiveUpdates`. Validate the whole batch on a scratch copy and apply all-or-nothing. Reject: any `ClientID` not prefixed by the authority-assigned member ID; per-update summed retain+delete length ≠ document length at that point; `\r` in inserted text; single insert >256 KiB; resulting UTF-8 document >512 KiB; pushes after baseline freeze (`TEXT_REJECT{reason:"locked"}`). Accepted batches ack the sender with `TEXT_ACK{document_id, version}` and broadcast `TEXT_UPDATES{document_id, from_version, updates}`.

Idle clients send `TEXT_CHECK{document_id, version, sha256(utf8(text))}`; mismatch forces `TEXT_SNAPSHOT{document_id, version, text, sha256}` resync for that client.
- Ingestion text enters the authority only through `INGEST_APPEND` (see the ingestion step) and is appended, never replacing human text.
- Starvation: clients retry with jitter; after 5 consecutive rejects show "sync lagging". Presence shows avatars/page indicators only; no in-text remote carets.

#### Session reducer and roles (NEW `internal/session/reducer.go`, untagged)

- Phases: `INGESTION → DELIBERATION → SYNTHESIS → APPROVING → APPROVED`, plus `APPROVING_UNKNOWN` (executor lost mid-write; resolved idempotently by `ARTIFACT_SAVED`) and terminal `CANCELLED`. `PAGE_TRANSITION` is emitted only by the authority as a consequence of a phase change. Owner-only commands drive phases: `FREEZE_REQUEST` (Page 1 confirm → DELIBERATION), `SYNTHESIZE_REQUEST{run_id, input_revision}` (→ SYNTHESIS), `RETRY_STAGE{run_id, stage_id}` (`run_id` must equal the current run, else `STALE_RUN`; for a failed stage while `cycle < max_cycles` it re-runs that stage under the same `run_id` with no `RUN_ASSIGNED` and `input_revision` continuing; when the run is paused at the max-cycles cap the authority assigns a new `run_id`, emits `RUN_ASSIGNED`, and resets the cycle counter to 1), `EDIT_BASELINE{baseline_rev}` (→ INGESTION), `CANCEL`, `APPROVE`.
- Roles: `owner` (room creator, the machine with the repository), `editor`, `viewer`. Owner only: confirm baseline, start/cancel runs, edit-baseline (rewind), approve. Editors: edit Page-1 text, resolve decision cards. Viewers: read only. Only the owner/executor uploads `.docx`/`.pdf`; parsing runs on that machine and original bytes are never mirrored.
- Every command carries `event_id`; the reducer dedupes the last 256 per member and returns the original result on retry.
- Counters are authority-assigned uint64, decimal strings on the wire: envelope `revision` = session-state revision, +1 per accepted state-changing command or phase change; envelope `epoch` = current lease epoch; `baseline_rev` +1 per freeze; `input_revision` per run, +1 per accepted `AVATAR_DRAFT`, `AVATAR_CRITIQUE` or `DECISION_RESOLVE`; `synthesis_rev` per run, +1 per accepted complete `synthesis.v1` draft; `expected_revision`/`approved_revision` = the envelope `revision` at that moment; `stage_id` ∈ {`pm`, `architect`, `specialist:<workstream_id>`, `critic`, `synthesizer`}.
- `run_id` is a UUIDv4 the authority assigns when it accepts `FREEZE_REQUEST` or an owner-requested rerun. It is broadcast in control event `RUN_ASSIGNED{run_id, baseline_rev, lease_epoch}` and in `STATE_SNAPSHOT`, passed to the executor as `RunInput.RunID`, and repeated in every `CYCLE_START`. `CANCEL` is session-terminal (phase `CANCELLED`, exit 130) and Page 2's control reads "Cancel session"; stopping only the run is `EDIT_BASELINE`.
- `DECISION_RESOLVE` is ordered by the authority; first valid write at the expected `input_revision` wins, later ones receive `ALREADY_RESOLVED` with the winning option.
- Approval command `APPROVE{baseline_rev, run_id, synthesis_rev, content_sha256}` (`content_sha256` = `synthesizer.ContentHash`, computed before any approval ID exists) is rejected with exactly one of `STALE_BASELINE`, `STALE_RUN`, `STALE_SYNTHESIS`, `DECISIONS_PENDING`, `BLOCKERS_OPEN`, `NOT_APPROVER`, `FENCED`.

#### Single executor lease

- Messages `LEASE_CLAIM → LEASE_GRANTED{epoch, ttl_ms}`, `LEASE_RENEW{epoch}`, `LEASE_RELEASE`, `LEASE_LOST{epoch}`. Epoch is a per-room monotonic uint64, incremented on every grant, never reset while the room lives (+1 after restore).
- TTL 15 s, renew every 5 s, measured on the authority's monotonic clock. Authority accepts executor events only when `from == holder && epoch == current`; otherwise replies `FENCED{current_epoch}` and drops them. The executor self-fences: no renewal ack within TTL−3 s cancels its LLM context and buffers output.
- The authority expires but never auto-elects. Eligible executor: owner only (the repository and AST graph live on that machine; cross-machine handoff is unsupported). A reconnecting executor with an unchanged epoch resumes. One executor guarantees one LLM pipeline: other clients never call providers.

#### Relay server (`cmd/relay/main.go`, `internal/relay/hub.go` — `//go:build server && !client`)

- WebSocket library: `github.com/coder/websocket` v1.8.15 (maintained successor of nhooyr; do not import `nhooyr.io/websocket` or gorilla). Per connection: one reader goroutine always reading, one writer goroutine with a 256-message bounded queue and 5 s write deadline, explicit ping every 15 s with 10 s pong timeout. `SetReadLimit(4<<20)` on every connection (4 MiB); queue overflow closes with 1013 and client resyncs; protocol violation closes 1008.
- Endpoints: `POST /sessions` (Bearer relay token) → `{relay_session_id, owner_secret, invite_secret}`; `relay_session_id` is 128-bit and secrets are 256-bit from `crypto/rand`; the relay stores only SHA-256 hashes and compares with `crypto/subtle`. `POST /sessions/{relay_session_id}/invites` (Bearer owner secret; body `{role: editor|viewer, max_uses: 1-10, ttl_seconds: <=86400}`) → `{invite_id, invite_secret}`; `DELETE /sessions/{id}/invites/{invite_id}` (owner). `POST /sessions/{id}/join` (Bearer invite secret) → `{member_id, member_secret}`. `GET /ws?session=<relay_session_id>` (Bearer owner or member secret; the query is advisory because the relay derives member identity from the secret) with subprotocol `plan-forge.v1`; close if `Subprotocol()` is empty. `GET /sessions/{id}/artifacts/{approval_id}/{name}` (Bearer owner or member secret), and `PUT` on the same path (Bearer owner secret plus header `X-Plan-Forge-Epoch`) allowed only in phase `APPROVING`/`APPROVING_UNKNOWN` for that `approval_id`, ≤4 MiB; the relay stores the bytes with its own SHA-256 and the hub accepts `ARTIFACT_SAVED{ok}` only when the reported hashes equal the stored ones; artifacts are kept 24 h. `GET /join/{id}` returns static text telling users to run `plan-forge join`. `GET /healthz`. Every client request carrying `Authorization` refuses redirects (`CheckRedirect` returns `http.ErrUseLastResponse`).
- Invites: role (`editor`/`viewer`), TTL default 24 h, max uses, revocation by owner. Invite URL form `https://<relay-host>/join/<relay_session_id>#<invite_secret>`; the fragment never reaches the relay. Interactive `plan-forge run --mode remote` prints this URL in the user's terminal; `--detach` output never contains it; `plan-forge invite --session ID` and the Page 1 header Copy button are the other places it appears.
- Member credentials: `POST /sessions/{id}/join` atomically consumes one invite use (default `max_uses=1`) and returns `{member_id, member_secret}` (256-bit, stored as SHA-256). `GET /ws` accepts only owner or member secrets; invite secrets are rejected there. Reconnects reuse `member_secret` without consuming uses. `INVITE_REVOKE` stops future joins; `MEMBER_REMOVE` closes that member's sockets with 1008. Invite defaults: `max_uses=1`, TTL 24 h. Clients store `owner_secret`/`member_secret` only in `PlanForgeHome()/sessions/<session_id>.cred` (0600, dir 0700) and delete it when the session ends — never in `.plan/state.json`, argv, logs or JSON output. Artifact routes accept `{name}` only equal to `synthesized_spec.md` or `plan_manifest.json`, `{approval_id}` only as a canonical UUID, and the session id only as a 128-bit hex value.
- Hardening: reject any request carrying an `Origin` header (browsers never talk to the relay); compression disabled; TLS required unless bound to loopback, or `--behind-proxy` is set together with a loopback/private listen address or an explicit `--trusted-proxy CIDR` (client IP for rate limits = rightmost `X-Forwarded-For` entry added by that proxy); per-IP and per-room rate limits; never log payloads or secrets; purge rooms 24 h after idle. Flags: `--port N` (supplied; binds `:N`, default 8443), `--listen HOST:PORT` (overrides `--port`), `--tls-cert`, `--tls-key` (supplied), `--auth-token-file PATH` or env `PLAN_FORGE_RELAY_TOKEN` — the supplied `--auth-token VALUE` is intentionally replaced because argv values are visible in process listings; passing `--auth-token` exits 2 with that explanation; on Unix the relay refuses a group- or world-readable token file. Also `--behind-proxy` and `--data-dir` (optional write-ahead log for restart recovery; without it the owner's local state reseeds the room).
- Privacy allowlist — never sent to the relay: `RepoContextGraph`, file contents, uploaded document bytes, credentials/tokens, environment, absolute paths, config. Allowed: the `prd` document, normalized PRD, avatar public summaries and drafts, critiques, decisions, and approved plan content. The client relay writer runs an egress check before every send: any decoded string value (never raw JSON bytes, because Windows backslashes are escaped there) containing the repo root, `$HOME`, `os.TempDir()`, `PlanForgeHome()` or `PlanForgeCache()`, each in its as-given and `filepath.EvalSymlinks` form, compared case-insensitively after normalizing `\` to `/`, with roots shorter than 4 characters skipped, is rejected for control events and redacted to `<local-path>` inside `public_summary` and draft `content` before `content_hash` is computed; tests use sentinel paths. The doc channel (`TEXT_DELTA`, `TEXT_UPDATES`, `TEXT_SNAPSHOT`, `TEXT_CHECK`) is exempt from path rejection because it carries user-authored shared text, which the join screen warns about. `SynthesisInput` validation replaces local-path matches with `<local-path>` before `ContentHash`, so the compiled spec, the `synthesis.v1` draft and the uploaded artifacts stay byte-identical to the on-disk files; redaction applies only to `public_summary` and non-synthesis draft bodies, computed before their hashes. A local path found in a `synthesis.v1` draft is a validation error (stage fails), and an egress hit during an artifact upload fails the approval with `ARTIFACT_SAVED{error:{code:"EOTHER"}}` without altering bytes. Plan text naming repository-relative files/symbols is plan content visible to room members; the join screen says so. The relay sees plaintext; no end-to-end encryption.
- Dependency proof: `go list -deps -tags server ./cmd/relay` MUST NOT match `internal/(ast|ingestion|host|avatars|storage|synthesizer|window|app|planstate)|/web$|tree-sitter|ledongthuc/pdf`.

#### Channels, replay and backpressure

- Doc channel (ordered by doc version): `TEXT_DELTA` (push), `TEXT_ACK`, `TEXT_REJECT`, `TEXT_UPDATES`, `TEXT_SNAPSHOT`, `TEXT_CHECK`.
- Control channel: one authority-assigned gapless `seq` per room for all other events.

- Local durable outbox per client binary under `PlanForgeCache()/recovery/<room>/`; unconfirmed edits on resync or late push export to `<room>-<ts>.md` and show in a recovery panel. Nothing is silently dropped.

#### Approval ordering (no Git)

1. Owner sends `APPROVE{baseline_rev, run_id, synthesis_rev, content_sha256}`. Authority validates, sets phase `APPROVING`, assigns `approval_id` (UUIDv4) and `created_at`, freezes doc pushes, `CYCLE_START`, `DECISION_RESOLVE` and lease changes, and emits `APPROVAL_PREPARED{approval_id, created_at}`. Solo mode runs the same authority in-process, with no relay upload.
2. Executor recomputes `ContentHash` and requires equality with `content_sha256`, compiles final bytes with `ApprovalMeta{approval_id, created_at}`, then `ArtifactStore.Commit` (journal in `.plan/transactions/`; prior pair rotated to `.plan/history/<ts>/`, keep last 5; `synthesized_spec.md` then `plan_manifest.json` as commit marker) and records the manifest hash in the local approval ledger. Remote mode: the executor then uploads both files with `PUT /sessions/{id}/artifacts/{approval_id}/{name}` (owner secret + current lease epoch, ≤4 MiB each, bound to the reported hashes, kept 24 h).
3. Executor replies `ARTIFACT_SAVED{ok, spec_sha256, manifest_sha256}` or `ARTIFACT_SAVED{error:{code, rel_path}}` with `code ∈ {EACCES, ENOSPC, EEXIST, EJOURNAL, EHASH, ESYMLINK, EOTHER}` and `rel_path ∈ {.plan/synthesized_spec.md, .plan/plan_manifest.json}`; free-form error text and absolute paths never leave the machine (the owner's UI shows the absolute path through a local-bridge-only event). Only on ok does the authority move to `APPROVED` and append `PLAN_APPROVED` copying those hashes. On error: back to `SYNTHESIS` with `ERROR{APPROVAL_FAILED}`. Executor lost mid-write → `APPROVING_UNKNOWN`; on return it reports on-disk hashes and the authority finalizes idempotently by `approval_id`.
4. Followers fetch both artifacts, verify SHA-256 against `PLAN_APPROVED`, record the hash in their local approval ledger, and write them the same journaled way into the `.plan/` of the folder chosen at `plan-forge join --repo` (Git or not, if writable). If the folder is not writable or the follower declines, the UI offers a download to a chosen path. They reply `ARTIFACT_SYNCED{ok|err}`; follower failure never reverts approval; the UI lists per-member sync state. Follower `join` exits 0 after artifacts are persisted (or the download is confirmed), 130 if the window closes before `PLAN_APPROVED`, 1 on sync failure.
5. Executor waits up to 5 s for `ARTIFACT_SYNCED`, stops the loopback server and exits 0. No `PLAN_APPROVED` is ever emitted before `ARTIFACT_SAVED ok`.

## Assumptions & contingencies
- Remote collaborators always install the client; the relay serves no browser UI (user decision). Approval writes and syncs artifacts but never stages/commits/pushes (user decision).
- AGY is always installed as a skill/hook host; AGY generation runs only when the isolated-config deny-rule + empty-`init`-tools gate passes; otherwise an authenticated Claude/OMP adapter runs the avatars; otherwise exit 3 (user decision: capability-gated adapter with safe fallback).
- Runtime prerequisites are an installed Chromium-family browser and optional local `pdftoppm`/`tesseract`; nothing is bundled (user decision).
- If `go mod tidy` or `SetLanguage` reports an ABI/version error with the pinned grammar set, pin each grammar to its newest tag whose `src/parser.c` declares `LANGUAGE_VERSION 14` and record the versions in `go.mod`; do not switch runtimes.
- If `claude --safe-mode` or `--permission-prompts` is rejected by the installed Claude Code, mark Claude `ErrCapability{"run: claude update"}` and continue down the adapter order.
- If `omp models --json` is not supported by the installed OMP, use configured model IDs. If the OMP plan-mode command or the OMP/AGY tool-call time limits cannot be confirmed, use the generic Plan Mode text and the `50s` wait timeout defined in Step 6.
- If the AGY hooks schema cannot be confirmed from its documentation at implementation time, ship AGY skills without the session-start hook and print the manual snippet.
- If Mermaid's SVG output requires broader CSP than `style-src 'self' 'unsafe-inline'`, keep `'unsafe-inline'` for styles only; never allow inline scripts.
- If OMP or AGY tool-call limits differ from the defaults assumed in `{{WAIT_TIMEOUT}}`, the installer regenerates skills with the verified values on the next run; `wait` stays stateless, so a killed call is retried rather than losing state.
- If the AGY isolated-config mechanism cannot be verified at implementation, AGY generation stays off (skills and hooks still install) and `/plan-forge` uses Claude or OMP, exiting 3 when neither is signed in.
- If a user has only Antigravity installed, `/plan-forge` exits 3 with the Claude Code/OMP guidance rather than silently using another provider.
- If `window.close()` is refused in `--app` windows on an OS, the binary still terminates its owned browser process after showing "safe to close".
- If GitHub `releases/latest/download/<asset>` does not resolve workflow-uploaded assets, the installers resolve the latest tag via `https://api.github.com/repos/danielckv/agentic-plan-forge/releases/latest` (`tag_name`) and download from `/releases/download/<tag>/`.
`internal/config/paths.go` (untagged) is the only code that resolves Plan-Forge state roots: `PlanForgeHome()` = `$PLAN_FORGE_HOME` when set (absolute, else exit 2), otherwise `~/.plan-forge` (Windows `%USERPROFILE%\.plan-forge`), directory 0700, holding the marker file `.plan-forge-home` (0600, created with the directory), `config.json`, `relay-token.json`, `install-manifest.json`, `backups/`, `approvals.json` and `sessions/<session_id>.cred`; `PlanForgeCache()` = `$PLAN_FORGE_HOME/cache` when set, otherwise `os.UserCacheDir()/plan-forge`, directory 0700, holding `run/`, `uploads/`, `sessions/<session_id>.{json,log}`, `recovery/` and `notices/`. No other package calls `os.UserConfigDir()` or `os.UserCacheDir()` (a unit test greps for both outside `paths.go`). Every path written elsewhere in this plan as `~/.plan-forge/...` or `os.UserCacheDir()/plan-forge/...` means `PlanForgeHome()/...` or `PlanForgeCache()/...`.
